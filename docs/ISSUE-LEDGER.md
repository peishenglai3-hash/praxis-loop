## Record rules

- Keep this file as the one ledger; do not copy it per iteration.
- Add one row per root cause, retaining every relevant run ID in the external evidence report.
- Use stable IDs and preserve old IDs when a fix changes implementation.
- Add the reproduction, first/last run, evidence manifest path and hash, impact, fix commit, regression case, and verification result before changing a status to VERIFIED_IN_SANDBOX.
- Keep task prompts, model transcripts, source diffs, and other private or large artifacts outside Git. Retain only minimal reproductions and summaries here.
- A static code path and a written test are not runtime reproduction. PL-003–PL-005 are now verified by the isolated Linux run below; this does not establish Windows-specific redirected-child semantics, which remain a separate platform limitation.

## Windows sandbox findings and run records

- **ENV-WIN-01 — redirected child spawn stalls:** the Windows adapter suite stopped in its first `ShellCommandAdapter.execute()` case before the Job Object observed any child process; the evaluator remained at one active process after the command's 5-second budget. The dedicated host tree test independently created a child and grandchild and verified kill-on-job-close, but that does not cover redirected stdio. `adapters.test.mjs` and `runner.test.mjs` are therefore excluded and explicitly unverified. Root cause is not attributed to Praxis Loop until reproduced in a compatible isolated runtime.
- **TEST-WIN-02 — SQLite row prototype assertion:** the first stability attempt compared a `node:sqlite` row with a plain object and failed because SQLite returns a null-prototype row. The integrity value itself was `ok`. The helper now compares row count, column name, and value separately; the complete 1000-cycle rerun passed.
- **STAB-WIN-01 — 10k projection-reopen cost:** before PL-006, the 1000-cycle run completed 1000 cycles, 10 reopens, and 11 integrity checks, but average reopen was 24.955 s. After PL-006, the same run completed in 228.7 s total; average reopen was 0.579 s. Search at 10k averaged 25.15 ms (p95 28.25 ms), RSS peaked at 190.1 MiB, host Job memory peaked at 245.2 MiB, handle count peaked at 183, active Job processes peaked at 1, and final SQLite main/WAL/SHM size was about 16.8 MiB. All sampled limits passed. This is a single local profile, not a universal performance guarantee.
- **STAB-WIN-02 — host sleep timing contamination:** the exploratory soak completed 3,570 cycles, 3 reopens, 23,570 events, and 10,000 memories. Three `quick_check` and one `integrity_check` returned `ok`; no sampled RSS/database/Job limit was breached. RSS peaked at 166.8 MiB; Job memory at 241.1 MiB; handles at 184; active Job processes at 1. Final database size was 18,083,840 B plus a 4,128,272 B WAL. The previously reported 2,999.6 s seed write overlaps a 2,998.4 s host telemetry gap and system sleep/wake record; QPC includes sleep time. Treat the duration as host-sleep contamination rather than a SQLite stall. The soak remains partial because command lifecycle was omitted.
- **MECH-WIN-01 — in-process subset:** `search-exploration.test.mjs` and `store.test.mjs` passed 16/16 tests. `adapters.test.mjs` and `runner.test.mjs` were not run. AppContainer preflight confirmed the no-capability token, host-sentinel denial, loopback denial, and descendant cleanup. The host had no available external-egress baseline, so external network blocking was not independently probed.
